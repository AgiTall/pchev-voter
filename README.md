# Pchev Voter

Discord-бот с двумя связанными системами: интерактивными партиями и выборами,
а также отдельными голосованиями в стиле ООН. Интерфейс построен на Discord
Embed, кнопках, Select Menu и Modal; ответы с персональным выбором отправляются
эфемерно и не засоряют канал.

Голосования ООН публикуют embed цвета `#102C4D` и показывают четыре варианта:

- ✅ **За** — зелёная кнопка;
- ⬜ **Воздержаться** — серая кнопка;
- ❌ **Против** — красная кнопка;
- 🛑 **Вето · админы** — доступно только участникам с правом Discord
  `Administrator`.

К каждому голосованию прикрепляется прямоугольная схема парламентского зала на
фоне ООН. Все участники сервера располагаются полукругом в несколько рядов.
Цвет рамки показывает выбор: зелёный — «за», серый — «воздержаться», красный —
«против», бордовый — «вето», тёмно-синий — голос ещё не отдан. Боты в зал не
добавляются.

Эмодзи настраиваются в `config/emojis.json`. Можно использовать обычные
Unicode-эмодзи, Discord-эмодзи `<:название:ID>` или анимированные эмодзи
`<a:название:ID>`. После изменения файла перезапустите бота.
Для вариантов второго типа используются отдельные настройки `choice1`–`choice5`.

Сообщение голосования выводится в компактном виде:

```text
🟡 Голосование активно

Кандидат: @Пользователь
Описание: текст голосования

Аргументы
✅ За: аргумент
❌ Против: аргумент

Результаты
✅ За: 0
⬜ Воздержались: 0
❌ Против: 0

Проголосовало: 0 из 21
До завершения: 00:35
```

Один участник имеет один голос и может изменить его до конца голосования.
Воздержавшиеся не учитываются при сравнении сторон. Решение принимается, если
голосов «за» больше, чем «против», при отсутствии вето. Любое вето блокирует
решение. Активные голосования сохраняются в `data/votes.json` и автоматически
восстанавливаются после перезапуска.

Если новый пользователь входит на сервер, бот автоматически добавляет его место
во все ранее созданные активные голосования, пересчитывает общее число участников
и перерисовывает парламентскую схему. При запуске выполняется дополнительная
сверка, поэтому пользователи, вошедшие во время простоя бота, тоже не потеряются.
Боты, дубли и уже завершённые голосования не затрагиваются.

> Discord не позволяет задавать произвольный цвет кнопки. Поэтому кнопка вето
> использует самый близкий встроенный красный стиль и отличается значком 🛑 и
> проверкой прав администратора.

## Установка

Понадобится Node.js 20.12 или новее.

1. Создайте приложение на [Discord Developer Portal](https://discord.com/developers/applications).
2. На вкладке **Bot** создайте бота и скопируйте токен.
3. Там же включите привилегированный **Server Members Intent** — он нужен, чтобы
   получить полный список участников сервера для парламентской схемы.
4. Скопируйте `.env.example` в `.env` и заполните `DISCORD_TOKEN`, `CLIENT_ID` и,
   для быстрого тестирования, `GUILD_ID`.
5. Пригласите бота с OAuth2 scopes `bot` и `applications.commands`. Ему нужны
   права **View Channels**, **Send Messages**, **Embed Links** и
   **Read Message History**. Для политических ролей также выдайте **Manage Roles**,
   **Manage Messages** и **Moderate Members**; роль бота разместите выше ролей
   Президента и помощников.
6. Установите зависимости и запустите бота:

```powershell
npm install
npm start
```

При каждом запуске бот обновляет slash-команду. С `GUILD_ID` она появляется на
выбранном сервере почти сразу. Без `GUILD_ID` регистрируется глобальная команда,
распространение которой может занять время.

## Партийная система

Вся работа игроков укладывается в три команды:

- `/parties` — список и статистика партий, просмотр состава, создание через
  Modal, вступление, выход и вход в кабинет Президента;
- `/election` — персональный бюллетень активных выборов, подтверждение голоса и
  live-результаты. Один пользователь имеет один голос и может изменить его до
  окончания срока;
- `/royal` — эфемерный пульт владельца/администратора: запуск и досрочное
  завершение выборов, импичмент и настройки.

Во время выборов состав и список партий замораживаются. По окончании срока бот
автоматически считает голоса. При единственном победителе лидер партии становится
Президентом; при ничьей или отсутствии голосов новый созыв не создаётся.

Президент открывает кабинет кнопкой в `/parties`, выбирает однопартийца через
User Select Menu и назначает до настроенного числа помощников. Бот создаёт две
управляемые роли:

- `Президент` — статусная роль без дополнительных разрешений;
- `Помощник президента` — временная роль с `Manage Messages` и `Moderate Members`.

Для выдачи и снятия ролей боту требуется **Manage Roles**, а его собственная роль
должна находиться выше управляемых ролей. Импичмент снимает только роли, созданные
этой системой, и не затрагивает обычные роли модераторов сервера.

Настройка стоимости создания партии сохраняется и показывается в интерфейсе.
Поскольку в проекте нет кошелька или экономики, сумма пока справочная и бот явно
сообщает об этом при создании партии. Для реального списания нужен адаптер к
экономической системе сервера.

Партии, бюллетени, созыв и настройки сохраняются в `data/politics.json` и
восстанавливаются после перезапуска. Discord ограничивает один Select Menu 25
вариантами, поэтому на сервере может быть не больше 25 партий.

## Команды голосования ООН

В Discord slash-команды используют именованные поля, поэтому команда выглядит
так:

```text
/set-vote заголовок:... кандидат:@Пользователь описание:... почему-за:... почему-против:... время:2ч
```

Второй тип позволяет задать от одного до пяти вариантов. Каждый пользователь
может выбрать один вариант и изменить его до завершения:

```text
/set-multi-vote заголовок:... описание:... время:2ч вариант-1:... вариант-2:... вариант-3:...
```

Примеры времени: `30m`, `2h`, `1d`, `1 час 30 минут`. Допустимый диапазон — от
1 минуты до 30 дней.

## Бесплатная работа на Render

В корне проекта находится `render.yaml`. Он создаёт бесплатный Web Service и
открывает маршрут `/healthz`, который нужен Render для проверки HTTP-порта.
Discord-бот продолжает работать в том же процессе.

1. Загрузите проект в отдельный репозиторий GitHub. Файлы `.env`, `data`,
   `node_modules` и `preview` исключены через `.gitignore`.
2. В Render создайте **Web Service**, подключите репозиторий и выберите план
   **Free**. Build Command: `npm ci`, Start Command: `npm start`.
3. Render найдёт `render.yaml` и попросит значения `DISCORD_TOKEN` и `CLIENT_ID`.
   Используйте новый токен, созданный через **Developer Portal → Bot → Reset Token**.
4. После Deploy откройте выданный адрес `https://...onrender.com/healthz`.
   Ответ с `"ok":true` означает, что проверка работает.

Бесплатный Web Service засыпает после 15 минут без входящих запросов. Внешний
аптайм-сервис может запрашивать `/healthz` чаще этого интервала. Однако файловая
система бесплатного сервиса временная: файлы `data/votes.json` и
`data/politics.json` стираются при засыпании, рестарте и новом Deploy. Для
гарантированного сохранения голосов, партий и созывов нужна внешняя база данных
или платный Persistent Disk.

`GUILD_ID` на Render не требуется: slash-команды регистрируются глобально.

### Перенос уже созданных локальных голосований

Файл `data/votes.json` не отправляется в GitHub, потому что содержит данные
участников Discord. Чтобы один раз перенести его на новый диск Render:

1. Откройте сервис в Render и перейдите в **Environment → Secret Files**.
2. Создайте Secret File с именем `votes-seed.json`.
3. Скопируйте в его содержимое весь локальный файл `data/votes.json`.
4. Сохраните настройки и выполните новый Deploy.

При запуске бот добавит из резервного файла отсутствующие голосования во
временное хранилище сервиса. На бесплатном плане не удаляйте Secret File: он
позволит восстановить эту резервную копию после рестарта. Голоса, добавленные
уже после создания копии, в неё автоматически не попадут.

Если Secret File не подхватился, администратор может выполнить в Discord
`/restore-votes`, прикрепить локальный `data/votes.json` и сразу восстановить
старые кнопки. Команда импортирует только голосования текущего сервера.
